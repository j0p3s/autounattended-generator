# Autounattend Generator

An interactive, browser-based generator for Windows 10/11 `autounattend.xml` answer files, with options inspired by [Winhance](https://winhance.net/).

Pick your settings in tabs (installation, user account, network, privacy, performance, power, updates, theme, taskbar, debloat, services…), preview the result, and download a ready-to-use `autounattend.xml`. Everything runs locally in your browser: no server, no tracking, no data leaves your machine.

**Live page:** <https://j0p3s.github.io/autounattended-generator/>

> **Disclaimer:** this is an independent project. It is not affiliated with, endorsed by, or generated by Winhance (memstechtips). It does **not** produce Winhance's official answer file; it produces a standard `autounattend.xml` with embedded PowerShell scripts that apply equivalent tweaks.

## Features

- **Windows setup:** all 38 Windows display languages, regional formats (dates, currency and the language for non-Unicode programs), 45+ keyboard layouts plus an optional second keyboard or your own `InputLocale` code, every Windows time zone, 80 countries for the home location, and a *Detect from this browser* button that fills them in. Edition (Ask, or generic keys for Home, Home N, Home Single Language, Pro, Pro N, Pro Education, Pro for Workstations, Enterprise, Education, or your own key), architecture, Windows 11 hardware-check bypasses (TPM, Secure Boot, RAM, CPU, storage, disk), optional automatic partitioning of the disk you choose (GPT/UEFI or MBR/BIOS), network disabled during setup, BypassNRO, .NET Framework 3.5, OOBE screen skipping, and an option to delete the setup scripts and the cached answer file after the next restart.
- **User account:** create a local account automatically (name, password, administrator or standard, one-time auto-logon), passwords that never expire, computer name (automatic, random generated by Windows, or custom with a random-name generator), registered owner and organization.
- **Network:** Wi-Fi profile (WPA2, WPA3 or open; names with accents and symbols work) saved and connected at first sign-in, automatic or static IPv4 on wired adapters, DNS servers (Cloudflare, Google, Quad9 or custom), Private network profile, IPv6 off, Remote Desktop. Network settings run as SYSTEM, so they also work with a standard account.
- **Privacy & security:** telemetry, advertising ID, error reporting, Bing in search, Copilot, Recall, activity history, location, BitLocker auto-encryption, Widgets, UAC level and SmartScreen.
- **Performance & gaming, Power, Updates, Notifications & sound:** registry and policy tweaks comparable to Winhance's *Optimize* categories, including Game Mode, HAGS, mouse acceleration, visual effects for best performance, power plans and timeouts, the F8 menu at startup (Advanced Boot Options with Safe Mode, as in Windows 7), Num Lock at startup, the Sticky Keys prompt and a really silent "No sounds" scheme. Turning off Memory Integrity (VBS) is available but never part of a preset.
- **Theme, Taskbar, Start menu, File Explorer:** tweaks comparable to Winhance's *Customize* categories, such as dark mode, taskbar alignment and buttons, *End task* on right-click, search highlights, the classic context menu, removing *Home* and *Gallery* from the navigation pane and long paths.
- **Debloat:** choose a level (*None*, *Minimal*, *Recommended* or *ULTIMATE*) and every included item is selected for you; each item stays adjustable. Covers built-in and sponsored apps, optional Windows features, OneDrive, Edge nags and telemetry tasks. Edge itself is never uninstalled.
- **Windows services:** choose a profile (*Default*, *Performance* or *Gaming*) and fine-tune each service. The *Gaming* profile also disables printing, Xbox, Remote Desktop, file sharing and more.
- **Software (winget):** install packages on first logon from a list of winget IDs (import a `winget-apps.json` produced by `winget export`), plus an *NVIDIA driver* option (silent install of a package copied to `C:\Drivers\NVIDIA` through `sources\$OEM$\$1\Drivers\NVIDIA`) and an *Extra registry settings* box for your own registry tweaks.
- **Your own scripts:** run a file from the USB drive at first sign-in (for example `Scripts\Programas.cmd`; `.cmd`, `.bat`, `.ps1`, `.exe` and `.msi`), and add your own PowerShell commands to the specialize pass (as SYSTEM) or to the first sign-in (as the user).
- **Search:** a search box above the tabs (press `/`) finds any option in every tab, including the entries of the lists (time zones, keyboards…).
- **Share a configuration:** *Copy link to this configuration* on the Generate tab creates a link that opens the page with your choices. Passwords, the Wi-Fi password and product keys are never put in the link.
- **Languages:** a language menu in the top bar. The base language is English (US); Portuguese (Portugal) is included. More languages can be added with a small dictionary (see *Adding a language*).
- **Presets, import/export:** a *Recommended* button on every tab (plus *Reset tab*), global *Recommended* and *Gaming* presets (the *Gaming* one sets up every tab for gaming); save and load your configuration as JSON.
- **Import an existing `autounattend.xml`:** the *Import XML* button reads a file (from this generator or another tool), fills in every option it recognizes in the tabs and lists, in a report at the top of the page, the settings and script lines that this page does not support and that would be lost when you generate a new XML. Files from other tools such as Winhance are supported: registry tweaks that match no option are kept in the *Extra registry settings* box (Software tab), and what cannot be converted (power plan, scheduled tasks, deletions of registry keys…) is summarised in the report.
- **XML preview and validation** with warnings for risky choices, a summary of your choices, plus a view of the embedded scripts.

## Usage

1. Open the generator: the GitHub Pages site of this repository, or open `index.html` locally in any modern browser.
2. Go through the tabs and choose your options.
3. Open **Generate XML**, check the warnings, then click **Download autounattend.xml**.
4. Place `autounattend.xml` in the root of your Windows installation USB drive (next to `setup.exe`), or add it to your ISO and save a new bootable ISO (see [Adding the file to an ISO](#adding-the-file-to-an-iso-and-saving-a-bootable-iso)).
5. Boot from the USB drive (or the new ISO) and install Windows.

> The interface starts in English (US). Use the language menu in the top bar to switch language. The choice is remembered, and you can also link directly with `?lang=pt`.

## Adding the file to an ISO and saving a bootable ISO

You can skip this if you install from a USB drive: just copy `autounattend.xml` to its root (next to `setup.exe`). Use the steps below when you want **one ISO that already contains the answer file**, for example to install in a virtual machine or to keep a ready-made image.

Windows Setup looks for `autounattend.xml` in the **root of the installation media**, so the file must end up there, with exactly that name (not `autounattend.xml.txt`).

### What goes where

| File or folder | Location inside the ISO | Needed for |
| --- | --- | --- |
| `autounattend.xml` | Root, next to `setup.exe` | Always |
| `NVIDIA` driver package folder | `sources\$OEM$\$1\Drivers\NVIDIA` | Only the *NVIDIA driver* option. Windows Setup copies it to `C:\Drivers\NVIDIA` |
| Your own file (e.g. `Scripts\Programas.cmd`) | The path you typed in *Run a file from the USB drive*, from the root of the media | Only that option. Keep the USB drive connected until the desktop appears, or put the file under `sources\$OEM$\$1` so that it is copied to `C:\` |

### Method 1: oscdimg (recommended, produces a BIOS + UEFI bootable ISO)

`oscdimg` is Microsoft's own tool for building Windows installation ISOs. It is part of the **Windows ADK**.

**1. Install the tool (once).** Install the [Windows ADK](https://learn.microsoft.com/windows-hardware/get-started/adk-install) and select only **Deployment Tools**. Then open **Deployment and Imaging Tools Environment** from the Start menu **as administrator**. `oscdimg` is already on the path there.

**2. Copy the ISO contents to a folder.** Right-click the original Windows ISO and choose **Mount**, then copy everything to a working folder (replace `X:` with the drive letter Windows gave the mounted ISO):

```
robocopy X: C:\ISO /E
```

You can also extract the ISO with 7-Zip into `C:\ISO`. Use a normal folder with at least 10 GB free.

**3. Add your files.**

- Copy `autounattend.xml` to `C:\ISO\` (the same folder as `setup.exe`).
- Optional, for the NVIDIA driver option: copy the unpacked driver to `C:\ISO\sources\$OEM$\$1\Drivers\NVIDIA\`. If the `$OEM$` folders don't exist, create them. Keep the names exactly as written, including the `$`.

Check that `C:\ISO` still contains `boot`, `efi`, `sources`, `bootmgr`, `setup.exe` and now `autounattend.xml`.

**4. Build the bootable ISO.** For a normal x64 ISO that boots on both BIOS (legacy) and UEFI PCs:

```
oscdimg -m -o -u2 -udfver102 -lWIN_UNATTEND -bootdata:2#p0,e,b"C:\ISO\boot\etfsboot.com"#pEF,e,b"C:\ISO\efi\microsoft\boot\efisys_noprompt.bin" C:\ISO C:\Win_unattended.iso
```

| Part | Meaning |
| --- | --- |
| `-m -o -u2 -udfver102` | Ignore the size limit, optimize duplicate files, use the UDF file system (needed for files above 4 GB, such as `install.wim`) |
| `-lWIN_UNATTEND` | Volume label of the ISO (any short name without spaces) |
| `-bootdata:2#p0,e,b"...etfsboot.com"` | First boot entry: BIOS / legacy boot |
| `#pEF,e,b"...efisys_noprompt.bin"` | Second boot entry: UEFI boot. The `noprompt` file skips the *"Press any key to boot from CD or DVD"* question, which is what you want for an unattended install |
| `C:\ISO` | The folder to turn into an ISO |
| `C:\Win_unattended.iso` | The new ISO to create (save it outside `C:\ISO`) |

If `efisys_noprompt.bin` is not in `C:\ISO\efi\microsoft\boot\`, use `efisys.bin` instead; the only difference is that you will have to press a key at boot.

**ARM64 images** boot only with UEFI, so use a single boot entry:

```
oscdimg -m -o -u2 -udfver102 -lWIN_UNATTEND -bootdata:1#pEF,e,b"C:\ISO\efi\microsoft\boot\efisys_noprompt.bin" C:\ISO C:\Win_unattended.iso
```

When it finishes, `oscdimg` prints the size of the ISO and `Done`. If it stops with an error instead, no usable ISO was made: check the paths in the command and that the folder contains `boot\etfsboot.com` and `efi\microsoft\boot\efisys*.bin`.

### Method 2: a USB drive instead of a new ISO

If you only need a bootable drive, you don't have to rebuild the ISO:

1. Write the original ISO to the USB drive with [Rufus](https://rufus.ie/) (or the Windows Media Creation Tool).
2. Copy `autounattend.xml` to the root of the drive.
3. Leave Rufus' own **Customize Windows installation** options unticked, because Rufus writes its own `autounattend.xml` in that case and it could replace yours.

With [Ventoy](https://www.ventoy.net/) you can copy the ISO you built with oscdimg onto the Ventoy drive and boot it from the menu.

### Save and test the ISO

1. Keep the final ISO under a clear name, for example `Win11_24H2_unattended.iso`. Don't edit the original ISO: keep it as the clean copy.
2. **Test it in a virtual machine first** (Hyper-V, VirtualBox or VMware). Boot the VM from the ISO and check that Setup runs without asking the questions you automated. Use a UEFI VM and a BIOS VM if you plan to use both.
3. Check the file in the ISO: mount it and confirm that `autounattend.xml` is in the root.
4. To put it on a USB drive, write the ISO with Rufus (choose **GPT** for UEFI PCs or **MBR** for BIOS PCs) or copy it to a Ventoy drive.

> **Warning:** if you use the automatic disk partitioning option, an unattended install **erases disk 0 without asking** as soon as the PC boots from this media. Label the ISO and the USB drive clearly, and don't leave them connected when you restart a PC you want to keep.

### Common problems

| Problem | Likely cause and fix |
| --- | --- |
| Setup ignores the answer file | The file is not in the root of the media, or is named `autounattend.xml.txt` (turn on *File name extensions* in File Explorer), or the XML is not valid. Generate it again and check the warnings in **Generate XML** |
| The ISO doesn't boot | It was built without the `-bootdata` part, or one of the boot files was missing. Rebuild it with the command above |
| Boots on UEFI but not on BIOS (or the reverse) | A boot entry is missing. Use the two-entry command for x64 |
| Boots but asks to press a key | You used `efisys.bin`; use `efisys_noprompt.bin` |
| `oscdimg` is not recognized | Open **Deployment and Imaging Tools Environment** as administrator, or call it with its full path: `C:\Program Files (x86)\Windows Kits\10\Assessment and Deployment Kit\Deployment Tools\amd64\Oscdimg\oscdimg.exe` |
| The language or edition is rejected | The language, edition and architecture in the XML must exist in the ISO you used |
| NVIDIA package not found after install | Check the folder is `sources\$OEM$\$1\Drivers\NVIDIA` at the ISO level and that you copied the unpacked files, not a `.zip` |

> 7-Zip and most archive tools can add files to an ISO, but they **cannot make it bootable again**. Use `oscdimg` (or another tool made for building boot ISOs) for the final ISO.

## How it works

The generated XML configures three Windows Setup passes:

| Pass | What it does |
| --- | --- |
| `windowsPE` | Language, hardware-check bypasses (`LabConfig`), optional disk layout, edition/product key |
| `specialize` | Extracts embedded scripts, `BypassNRO`, disables network adapters, runs `system.ps1` (HKLM policies, Appx removal, default-user profile) and registers the one-time `WinTweaks-FirstBoot` task |
| `oobeSystem` | Hides OOBE screens, creates the local account and runs `firstlogon.ps1` at the first sign-in |

PowerShell scripts are stored inside a custom `<Extensions>` element of the XML. A short specialize-pass command reads `C:\Windows\Panther\unattend.xml` and writes them to `C:\ProgramData\WinTweaks\`. This avoids the command-length limit of `RunSynchronousCommand`. Logs are written to the same folder (`system.log`, `firstboot.log`, `firstlogon.log`).

| Script | Runs | Contains |
| --- | --- | --- |
| `system.ps1` | specialize pass, as SYSTEM | Registry and policy tweaks, default-user profile, services, Appx removal, your specialize commands |
| `firstboot.ps1` | first sign-in, as SYSTEM, through the one-time `WinTweaks-FirstBoot` scheduled task | Network adapters back on, Wi-Fi, IP and DNS settings, power plan, NVIDIA driver, cleanup task |
| `firstlogon.ps1` | first sign-in, as the user (`FirstLogonCommands`, elevated for administrators) | Region, per-user tweaks for the first user only, winget, your file from the USB drive, your first sign-in commands |

Machine-wide work runs in `firstboot.ps1` because `FirstLogonCommands` only run without a prompt for administrators: with a standard account, Windows asks for an administrator password first. The task waits until OOBE is over, so the network stays off during OOBE when you ask for it.

User-level tweaks (theme, taskbar, Explorer…) can be applied either to the default user profile (all new users) or only to the first user that signs in.

## Safety notes

- **Disk wipe:** the optional automatic partitioning erases the chosen disk (disk 0 unless you change it) without asking. It is off by default and highlighted in the UI. Check the disk number with `diskpart` → `list disk` and test in a virtual machine first.
- **Passwords:** a password set for the local account is stored in plain text inside the XML (and in `C:\Windows\Panther`). Never commit or share an XML that contains a real password.
- **Wi-Fi password:** like the account password, it is stored in plain text in the XML. An option removes it from the scripts and from `C:\Windows\Panther` after the profile is saved, but the XML on your USB drive keeps it. The *Delete the setup scripts and the cached answer file* option removes the copies left on the PC.
- **Network settings:** Wi-Fi, IP and DNS settings are applied at first sign-in by a SYSTEM task, for any account type. A static IPv4 address is applied to every wired adapter unless you restrict it by adapter name.
- **Standard account:** if the only account is a standard user, the PC has no administrator account, and Windows asks for an administrator password before it runs the first sign-in script.
- **Your own commands:** they are copied into the scripts as they are. Check them in the preview on the Generate tab.
- **Policies:** many tweaks use Group Policy registry keys. Windows may show "Some settings are managed by your organization". This is expected.
- **Updates:** disabling automatic updates stops security patches until you re-enable them.
- **Language:** the UI language you choose must exist in your Windows ISO.
- **Windows 11 24H2 and later:** `BypassNRO` may be ignored by newer builds. Creating the local account in the XML avoids the problem.
- Test status: the generator and the XML output were checked with automated tests (syntax, well-formedness, UI smoke test). Real-world installs on all Windows builds have not been exhaustively tested. Review the output and use at your own risk.

## Adding a language

All UI text in `index.html` is written in English (US), which is the base language. Other languages are dictionaries that map the English text to its translation.

1. Copy the `PT` dictionary (the `const PT={ ... }` block) and translate the values.
2. Register it: `DICTS.xx = XX;` right after the dictionary.
3. Add one entry to `UILANGS`, for example `{code:'es', name:'Español', html:'es-ES'}`.

Any string without a translation falls back to English, so a partial translation works. Pull requests with new languages are welcome.

## What's new

- First sign-in work that needs administrator rights (network back on, Wi-Fi, IP, DNS, power, NVIDIA driver) now runs as SYSTEM in `firstboot.ps1`. Before, a standard account kept the network disabled after setup.
- Registry lines use PowerShell single quotes: values with `$` or a backtick are written as typed, and empty values (the classic context menu) no longer lose their `/d` argument in Windows PowerShell.
- *No sounds* now clears every event sound; *Visual effects for best performance* also sets `UserPreferencesMask`; *Disable Recall* adds `AllowRecallEnablement=0`.
- The Delivery Optimization service is no longer disabled in the Gaming service mode (it can break Windows Update and Store downloads); the Delivery Optimization policy is used instead.
- *Passwords never expire* uses `net accounts /maxpwage:UNLIMITED` in the specialize pass, so it also works for standard users and OOBE accounts.
- The regional format also sets the language for non-Unicode programs (`SystemLocale`).
- Wi-Fi profiles include the SSID in hex, so names with accents work.
- New options, full language/keyboard/time zone/country lists, disk number and MBR layout, cleanup, your own scripts, search, configuration links and a summary on the Generate tab.
- XML files made by older versions of this page import without false "unsupported" reports.

## F8 menu (Advanced Boot Options)

*Power → Startup → Enable the F8 menu at startup* runs `bcdedit /set {current} bootmenupolicy Legacy` during setup, so that on Windows 10 and 11 you can tap **F8** right after the PC maker's logo to open Safe Mode, Safe Mode with Networking, *Disable driver signature enforcement* and the other options of Windows 7. It always works after **Restart**; after a shutdown it works only with *Disable fast startup* turned on, because fast startup resumes Windows instead of starting it. Firmware fast boot and wireless keyboards can also make the F8 window too short.

To turn it off later, run `bcdedit /set {current} bootmenupolicy Standard` in an administrator Command Prompt.
